# CyberRange — Ansible Configuration

Companion to the Terraform infrastructure build. Configures every VM after Terraform creates it.

## Directory Structure
```
ansible/
├── ansible.cfg                       # become=False globally (set per-play in site.yml)
├── site.yml                          # Master playbook — runs everything
├── setup-offline-mirror.sh           # ONE-TIME offline mirror builder (run on Terraform server)
├── inventory/
│   └── hosts.ini                     # AUTO-GENERATED by backend on every deploy
├── group_vars/
│   ├── all.yml                       # Creds, wazuh_manager_ip, OFFLINE MODE settings
│   ├── web_servers.yml               # * MULTI-WEBSITE list (name + port + php)
│   └── windows_clients.yml           # WinRM settings
├── playbooks/
│   ├── servers.yml                   # Servers only
│   └── agents.yml                    # Agents only
└── roles/
    ├── offline-repo/                 # * NEW — points apt at local mirror (runs first)
    ├── wazuh-server/                 # * Manager + Indexer + Dashboard (full stack)
    ├── web-server/                   # * Multi-website Apache (one vhost per site)
    ├── db-server/                    # MariaDB
    ├── ftp-server/                   # vsftpd
    ├── wazuh-agent/                  # Wazuh Agent for Linux (+ auto-registration)
    └── wazuh-agent-windows/          # Wazuh Agent for Windows (WinRM)
```

## OFFLINE / AIR-GAPPED MODE

All roles install software from a local mirror hosted on the Terraform server,
so the target VMs never need internet access.

### One-time setup (on the Terraform server)

    cd ansible

    # PHASE A — download every package + file (needs internet ONCE)
    sudo ./setup-offline-mirror.sh download

    # PHASE B — start the mirror HTTP servers (no internet needed after this)
    sudo ./setup-offline-mirror.sh serve

    # Or both at once if the Terraform server has temporary internet:
    sudo ./setup-offline-mirror.sh all

This creates:
- http://<terraform-ip>:8080 — apt package mirror
- http://<terraform-ip>:8081 — file mirror (Wazuh MSI, certs tool, etc.)

Both run as systemd services (offline-apt-mirror, offline-files-mirror) so they survive reboots.

### Then configure the IP

Edit group_vars/all.yml:

    offline_mode: true
    offline_repo_host: "10.0.40.23"   # <- your Terraform server IP

To go back online (e.g. for testing), just set offline_mode: false.

## MULTI-WEBSITE HOSTING

The web-server hosts as many websites as you want, each on its own port.

To add a website:
1. Create a folder: roles/web-server/files/sites/<name>/
2. Drop your .html / .php files inside (entry point: index.html or index.php)
3. Add an entry in group_vars/web_servers.yml:

       websites:
         - name: my-new-site
           port: 8004
           php: true        # true = PHP site, false = static HTML

4. Re-run: ansible-playbook site.yml --limit web_servers

The site goes live at http://<web-server-ip>:8004. Each site is its own Apache
virtual host with its own logs. PHP is installed automatically if any site needs it.

## ICP / SHIKRA INSURANCE VULNERABLE APP

The web server also deploys the ICP / Shikra Insurance training app — a
self-contained vulnerable web application with 27 deliberate vulnerabilities
across 6 subdomains. It ships its own installer (PHP detect, MySQL, schema/seed,
Apache vhost, per-install secret flags).

It is handled by the icp-website role and lives in:
    roles/icp-website/files/icp-app/

Controlled by deploy_icp in group_vars/web_servers.yml:
    deploy_icp: true     # set false to skip the ICP app entirely

It owns port 80 with name-based subdomain vhosts:
    icp.lab  www.icp.lab  policies.icp.lab  claims.icp.lab
    status.icp.lab  beneficiary.icp.lab  admin.icp.lab

After deployment, on any machine that will browse the range, add those
subdomains to /etc/hosts pointing at the web server IP. The ICP app and your
own custom websites (ports 8001+) run side by side on the same web server.

WARNING: this app contains REAL exploitable vulnerabilities (SQLi, RCE, file
upload, etc.). Only deploy it inside the isolated cyber range.

## WAZUH FULL STACK

wazuh-server role installs and auto-configures all three components:

| Component       | Port        | Purpose                                   |
|-----------------|-------------|-------------------------------------------|
| Wazuh Manager   | 1514 / 1515 | Detection engine, agent registration      |
| Wazuh Indexer   | 9200        | OpenSearch backend storing alerts         |
| Wazuh Dashboard | 443         | Web UI — https://<wazuh-ip> admin/admin   |

Certificates are generated on-box with wazuh-certs-tool (single-node).
Filebeat ships Manager alerts into the Indexer automatically.

## Usage

    # Full pipeline
    ansible-playbook site.yml

    # Connectivity test
    ansible servers,linux_clients -m ping
    ansible windows_clients -m win_ping

    # Single group
    ansible-playbook site.yml --limit web_servers
    ansible-playbook site.yml --limit wazuh_servers
    ansible-playbook site.yml --limit db_servers

    # Staged
    ansible-playbook playbooks/servers.yml
    ansible-playbook playbooks/agents.yml

    sudo apt install ansible sshpass python3-pip -y
    ansible-galaxy collection install ansible.windows community.general

## One-time Windows VM prep (WinRM)

If not using Cloudbase-Init, run inside each Windows VM:

    winrm quickconfig -q
    winrm set winrm/config/service '@{AllowUnencrypted="true"}'
    winrm set winrm/config/service/auth '@{Basic="true"}'
    netsh advfirewall firewall add rule name="WinRM" dir=in action=allow protocol=TCP localport=5985
